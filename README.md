# bama-enconvo

Enconvo packaging for https://github.com/daveebbelaar/bama: all 21 skills packaged as one updatable plugin.
Generated by the repo-to-plugin project skill; upstream clones stay pristine - never edit them.

## Install

```sh
npx -p @enconvo/api enconvo plugin install Iteractive-Development/bama-enconvo
```

or **Plugins → Add → Add from GitHub…** and paste `Iteractive-Development/bama-enconvo`.

## What a fresh install delivers

Everything the plugin ships loads through documented Enconvo mechanisms, with no post-install step:

- **21 skills** — every `skills/<name>/SKILL.md` is loaded globally (Plugin Formats › Skills: "Enconvo loads every `skills/<name>/SKILL.md`"). Every Agent sees every enabled skill.
- **5 helper agents** — every `agents/<name>.md` (`start`, `plan`, `code`, `design`, `ship`) loads as a helper an agent can hand work to, and appears in the composer's `@` menu (Plugin Formats › Agents, Enconvo 2.5.7+).

## Optional: per-agent skill sets

By default every Agent sees all skills above. If you want an Agent to see only some of them, use Enconvo's per-Agent **Skills** setting (Settings → Agent List → the Agent → **Skills**) — the documented mechanism; add the skills you want it to carry and disable the rest for that Agent. Nothing in this repo needs to run for that, and no script here is a runtime dependency.

The grouping the series was designed around, for anyone recreating it through that setting:

| Agent | Skills |
| --- | --- |
| Mac App Starter | app-brief, bama, new-mac-app, swift-swiftui |
| Mac App Planner | app-brief, clone, research, user-stories, ux-design |
| Mac App Engineer | agent-cli, improve-architecture, improve-loop, mac-design, os-integrations, performance, swift-swiftui, ux-design |
| Mac App Designer | app-icon, design-from-app, design-kit, design-system, layout-grid, mac-design, ux-design |
| Mac App Release Engineer | build-and-verify, layout-grid, test-mac-app |

> The previous packaging marked every skill `visibility: scoped` (an undocumented key) and relied on a machine-local linking script, so a fresh install exposed no skills at all. That was removed on 2026-11-02; skills now load the documented way.

## Update flow

Installed from GitHub, the plugin updates with **Plugins → bama-enconvo → Check for updates**, or by re-running the install command above.

To rebuild from the upstream repo (maintainer flow, needs the repo-to-plugin workspace):

```sh
python3 ~/Projects/Agent\ Plugins/.enconvo/skills/repo-to-plugin/scripts/new_plugin.py sync --config <adapter>/build-config.json
```

`build-config.json` and `agent-map.json` are maintainer build inputs; Enconvo loads neither. `agents/` is what ships the helpers.
